## Language rules

- No `any`. Use `unknown` and narrow. ESLint `@typescript-eslint/no-explicit-any: error`.
- Named exports only. No default exports (scenario files are the one exception: they default-export a scenario).
- Prefer `readonly` fields and `ReadonlyArray`. Mutation is allowed inside market implementations, hidden behind the interface.
- Exhaustive `switch` on discriminated unions with a `never` check.
- Functions do one thing; keep most under ~30 lines.
- No classes where a function will do. Classes are fine for stateful markets and the engine.
- File names: `kebab-case.ts`; one main export per file; tests beside the file.

## Money and math (ADR 0003)

- **Units:** quote in lamports (`bigint`), base in token base units (`bigint`), percentages in basis points (`bigint` inside math, `number` allowed in config before parsing).
- **Prices:** represented as a `Price` value object `{ num: bigint; den: bigint }` (quote per base, both in base units). Compare with cross-multiplication; never divide early.
- **Fixed point for display only:** conversion to decimal strings happens in `report` via `formatUnits(value, decimals)`.
- **Rounding:** favor the pool (floor outputs, ceil inputs). Every rounding site has a comment `// round: pool-favoring`.
- **Helpers live in `core/src/math/`:** `ceilDiv`, `mulDiv`, `bpsOf`, `minBig`, `maxBig`, `pctOfPeak`. Each fully tested with properties.
- `number` math is allowed only for counts, indices, slot numbers (safe integers, asserted), and SVG coordinates.

## Errors

```ts
export class LaunchsimError extends Error {
  constructor(readonly code: ErrorCode, message: string, readonly details?: unknown) {
    super(message);
    this.name = "LaunchsimError";
  }
}
```

- `ErrorCode` is a string union (`"invalid-config" | "division-by-zero" | ...`), stable across versions.
- Expected market outcomes are data (`TradeOutcome`), not exceptions.
- Never swallow errors. Never `catch` without narrowing `unknown`.

## Validation at boundaries

Every external input (scenario files, CLI args, HTTP params, stored JSON) is parsed with zod `.strict()` schemas. Inside `core`, types are trusted.

## Documentation

- **TSDoc on every export:** one-sentence summary, `@param`, `@returns`, `@throws`, and an `@example` for public API.
- **Why, not what:** inline comments explain intent or a non-obvious choice (e.g. rounding direction), not what the code obviously does.
- **Docs-as-code:** a PR that changes behavior updates the matching `docs/` page. Reviewers check this.
- API reference generated by TypeDoc (`pnpm docs:api`) into `docs/api/` (gitignored, published with releases).
- Every package has a short `README.md`: purpose, install, one example, link to docs.

## Lint and format

- ESLint flat config with `typescript-eslint` `strictTypeChecked` and `stylisticTypeChecked`.
- Custom rules: no `Math.random`/`Date.now` in `core`; no Node I/O imports in `core`; coverage-ignore comments must include a reason; `index.ts` re-exports only.
- Prettier defaults, 100-char width.
- `pnpm lint` must pass with zero warnings (`--max-warnings 0`).

## Commits and PRs

- Conventional Commits: `feat`, `fix`, `test`, `refactor`, `docs`, `chore`, `perf`, `ci`, with package scope.
- PR description: what behavior changed, which tests prove it, which docs changed.
- Keep PRs small. A PR that adds a check includes: the check, its tests, its registration, its doc row, and a scenario using it.
